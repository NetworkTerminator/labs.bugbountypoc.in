📖 Deep Explanation:

  • The application takes user input (name) from the URL and directly inserts it into the page using innerHTML without sanitization.
  • Since the input is reflected inside the normal HTML body context, the classic <script> injection works perfectly.
  • When the page renders, the browser executes the malicious JavaScript inside <script> tags.
  • In real-world apps, <script> may be filtered, which is why alternative payloads like <img src=x onerror=...> are often used.
  • Key lesson: Always analyze the injection context. Here it was raw HTML, so <script> execution was the simplest and most effective.
